# TL;DR
> ⚠️本文基于pipewire音频环境实现。

不想走蓝牙，但想走wifi（甚至支持easytier）传输音频。

> 哦对了顺道安利一个设备内的pipewire音频路由管理工具`qpwgraph`，十分的炫酷且好用啊！


# 只传输单个软件
> 此方法也可以让termux当作接收机放歌！

发送端运行：
``` bash
PULSE_SERVER=tcp:接收机ip地址 你要运行的软件
```
比如我要运行amberol听歌：
``` bash
PULSE_SERVER=tcp:192.168.1.14 amberol
```


接收端运行：
``` bash
pactl load-module module-native-protocol-tcp "auth-ip-acl=127.0.0.1;192.168.1.0/24" auth-anonymous=1
```
> 这里192.168.1.0/24是发送机所在的网段，你也可以给他写个`/32`的指定单台机器。

关闭：
只需要在接收端运行：
``` bash
pactl unload-module module-native-protocol-tcp
```



# 传输整机音频
## 简单上手
将两台机器置于同一局域网下。


发送机运行：
``` bash
pactl load-module module-rtp-send source="$(pactl info | sed -n 's/^Default Sink: //p').monitor"
```


接收机运行：
``` bash
pactl load-module module-rtp-recv
```


关闭很简单，在两台电脑上分别执行：
``` bash
pactl unload-module module-rtp-recv

pactl unload-module module-rtp-send
```



## 双网卡、弱网环境
将PVE和工作电脑连到同一个wifi（192.168.31.0/24），但以太网不在同一个网段，怎么通过pipewire无线传输音频？

首先我们看pve和工作电脑的组播地址路由规则：
``` bash
╭─pve@pve ~    
╰─$ ip route get 224.0.0.56  
multicast 224.0.0.56 dev vmbr0 src 10.114.51.4 rt_offload_failed uid 1000    
   cache <mc>
```

再看我们工作电脑的：
``` bash
┌─[enoch@admin] - [~] - [Wed Nov 25, 22:24]  
└─[$] <> ip route get 224.0.0.56  
multicast 224.0.0.56 dev 无线网卡 src 192.168.114.51 rt_offload_failed uid 1000    
   cache <mc>
```

好，都不走wifi的那个网卡。我们给他改过去。
在PVE上执行：
``` bash
sudo ip route replace 224.0.0.56/32 dev 无线网卡 src 无线网下pve的ip
```

在工作电脑上执行：
``` bash
sudo ip route replace 224.0.0.56/32 dev 无线网卡 src 无线网下工作电脑的ip
```

然后回到pve启动监听：
``` bash
pactl load-module module-rtp-recv
```

再在工作电脑上启动发送：
``` bash
pactl load-module module-rtp-send source="$(pactl info | sed -n 's/^Default Sink: //p').monitor" enable_opus=true source_ip=无线网下工作电脑的ip
```
> 开了`enable_opus=true`可以让传输过程经过压缩而非直接传原始码流，当然也可以换成手动指定码率和声道的参数`rate=22050 channels=1`

这样就好啦！


关闭方法同上。
